# 0003. 게스트 SSH 서버: Dropbear

- 상태: 채택 (2026-10-18)

## 맥락

PC에서 VS Code Remote-SSH·scp·rsync로 들어오려면 glibc 게스트 안에 SSH 서버가 필요하다
(VS Code 서버는 Termux의 bionic libc에서 동작하지 않는다).

## 실측

- OpenSSH `sshd`(Ubuntu 24.04, 9.6p1): 접속 시 proot가
  `./path/path.c:546: compare_paths2: assertion "length1 > 0" failed`로 중단(SIGABRT).
- Dropbear(`dropbear-bin`) + `openssh-sftp-server`: 키 인증 접속, 원격 명령, scp(sftp),
  `-L` 포트 포워딩 동작.
- 백그라운드 데몬은 로그인 세션 종료 시 함께 정리되므로(`--kill-on-exit`) proot-distro
  분리 세션(`login -d`)으로 띄워야 유지된다.

## 결정

Dropbear를 `-F -E -R -s -w`(포그라운드, 첫 사용 시 호스트 키 생성, 키 인증만, root 금지)로
분리 세션에서 실행하고 `andlinux svc`가 PID를 관리한다. 기본 포트 2222, 바인딩 0.0.0.0
(키 인증만이므로 LAN/Tailscale 접속 허용). 키가 없으면 시작하지 않는다.
